## 核查 UbbTextBlock 属性解析能力（主属性 / 键值对属性）

需求：`[img=1]`、`[img="http…"]`、`[topic=1029383]` 这类「主属性」，以及
`[audio,title=…,author=…]url[/audio]` 这类「键值对属性」（顺序无关，需落到属性字典）。

核查方式：建临时探针工程 `%TEMP%\ubb-attr-probe`（`EnableDefaultCompileItems=false`，
直接 Compile Include 仓库里的 `Tokenizer/*.cs` + `Parser/*.cs`，纯 C# 无 WinUI 依赖），
打印 Token 流 + AST 属性字典逐条比对。

结论：**部分满足，需求未全部实现**。

已可用：
- 主属性（不加引号）：`[img=1]`、`[img=url]`、`[topic=1029383]`、`[color=#f00]`、`[size=5]`
  → 落到 `value`（按类型经 `UBBParser.GetAttributeName` 映射为 href/color/size/font/language/author）。

缺陷：
1. 【P0】键值对属性完全没拆。`[audio,title=X,author=Y]` →
   `value="title=X"`、`value1="author=Y"`。键是 `value{n}` 而非 `title`/`author`，
   且谁在前谁拿 `value`（顺序敏感）。根因：`Tokenizer.IsTagDelimiter` 只在
   `_lastType == LeftBracket/Slash` 时把 `=` 当分隔符，逗号后整段 `key=value` 被扫成一个 AttrValue；
   解析器又只按 `attrCount` 编号。
2. 【P0】属性值不去引号。`[img="http://…"]` → `value="\"http://…\""`，
   `ImageRenderStrategy` 的 `IsValidUrl` 判定失败 → 图片不渲染；`[topic="1029383"]` 同理被丢弃。
3. 【P1】值前后空格不裁剪：`[audio, title=X , author=Y ]` → 值带空格。
4. 【P1】引号内逗号被当分隔符：`[audio,title="虽然,歌声"]` 被切成两个属性。
5. 【P2】主属性里的逗号会截断值：`[url=https://a.com/x,y]` → `href="https://a.com/x"` + `value1="y"`。
6. 【P2】渲染层下游未适配：`AudioRenderStrategy:806` 仍是
   `title.Replace("title=", "")` 的特判 hack；`MusicPlayer` 只有 `Title`，没有 author 展示位。

建议修复（最小改动面）：
- `Tokenizer.ScanTagContent`：引号感知（仅将 `"` 视作成对引号，**不要**把 `'` 视作引号，
  否则 `title=Don't Stop` 之类的撇号会吞到 EOF）。
- `UBBParser.ParseTagHeaderOrFallback`：区分分隔符——`Equal` 进来的是主属性
  （key 走 `GetAttributeName`），`Comma` 进来的是键值对（在该 AttrValue 的**第一个** `=` 处切分，
  key/value 各自 Trim + 去引号）；无 `=` 时回退 `value{n}` 保持兼容。
- `RenderStrategy.AudioRenderStrategy`：改读 `title` / `author` 命名属性，删掉 `Replace` hack。

其他发现：未知标签（如 `[content,type=a]`）会整体回退成文本，属预期行为。

## 【需求澄清】引号不是 UBB 语法

用户澄清：**附加属性一般没有引号，引号只是普通字符串，不在 UBB 语法里**，
所以上面第 2、4 条（去引号 / 引号内逗号）**不作处理**。
真正要解决的是：**逗号到底是不是属性边界**——`title=Hello, World,author=A` 里第一个逗号属于标题内容。

## 【试验中，未落盘主工程】播放器五个问题的定位与修复

用户回报：播放正常但底部报"初始化失败"、按不动暂停；slider 播放时卡在开始；律动条不动且形态不对；
颜色用了魔法数字。

**同一个根因**：`UpdatePlayPauseButton()` 里 `EqualizerStoryboard.Begin()` 抛异常。
那个 Storyboard 写在 `UserControl.Resources` 里 —— **资源字典有独立命名域**，
`Storyboard.TargetName` 解析不到可视树元素 → `Begin()` 抛 → 
`InitializeAndPlay` 的 catch 把它当成"初始化失败"，同时后面的 `_progressTimer.Start()` 永远执行不到。
所以出现"音频在播 + 报初始化失败 + 进度条不动 + 按了没用（`_isInitialized` 被打回 false，点一次就重新初始化一次）"。

修复：
1. 动画改在代码里挂：`SetupEqualizer()` 里 `Storyboard.SetTarget(anim, scaleTransform)` +
   `SetTargetProperty(anim, "ScaleY")`，彻底不依赖名字解析。
2. **拆 try**：`EnsureInitializedAsync()` 只管"加载媒体源"，失败才算初始化失败；
   `TogglePlayPause()` 放到另一段 try 里，UI 异常不再污染播放状态。
3. 律动条：`VerticalAlignment="Bottom"`（原来默认 Stretch 导致顶对齐）、宽度 3、高度 6/12/9。
4. 颜色：`LightSeaGreen` / `DarkCyan` / `Teal` / `White` / `Transparent` 等命名色，
   主题相关的交给 `{ThemeResource}`；主色做成 `PlayerAccentBrush` 等资源再用 `<StaticResource ResourceKey=...>` 别名。
5. 预览宿主的 `DispatcherQueue.CreateTimer()` 必须**存字段** —— 不被 DispatcherQueue 强引用，
   局部变量被 GC 后 Tick 就不再触发（表现成"第一个定时器好使，第二个不触发"）。

验证（全部在 `%TEMP%\player-preview` 里做的，主工程一行没动）：
本地生成 60s 的 WAV 当音源，用 `PREVIEW_MODE=play / playstop` 两种模式跑：

但进度条**轨道**下沿到卡片内底 = **38 DIP**。多出来的 22 来自两处：
- WinUI 的 `Slider` 自有布局盒比轨道高得多（约 32~40 DIP，轨道只占其中 4），
  盒底那段空白是看不见的 → 视觉上多了约 18；
- 状态行（加载条/错误文字）那一格虽然子元素都 Collapsed，但它头上的 `Margin="0,8,0,0"` 仍然占 8 DIP。

改法：
- 状态行的外边距挪到两个子元素身上（都折叠时这一行真的 0 高）；
- 进度行 `Height="20"` + 滑块 `VerticalAlignment="Center"`；
- 卡片 `Padding` 改成 `16,16,16,14`（下边距比上边距小，用来抵消滑块盒底那段空白）。

实测复验：海报上沿→内顶 **16.0 DIP**，轨道下沿→内底 **16.0 DIP** ✓，卡片内高 116.3 DIP。
**这类"看起来不平衡"的问题必须量，不能靠调数字猜**——滑块盒子里那段空白肉眼完全看不出来。

**2. 方案 A 落地**
- 头部行加第三列，放两个 32px 图标按钮（下载 + 音量），`VerticalAlignment="Top"`。

  一半探出卡片外），`FlyoutPresenterStyle` `BasedOn="{StaticResource DefaultFlyoutPresenterStyle}"`
  去掉默认厚内边距、圆角 6。实测这个 BasedOn 的 key **存在**，能用。
- 浮层里是「静音小按钮 + 音量滑块」；外面那颗的音量图标跟着当前音量在 `\uE767`/`\uE74F` 之间切。

## 【重构】海报只用一张 Image，去掉叠层的占位图

用户指出：`PosterPlaceholder`（XAML 里 `ms-appx` 那张）+ `PosterImage`（自定义地址）两张 Image 叠着，
「识别到没有 poster 的时候改 PosterImage 的 Source 就行了，不需要多放一个控件」。

**判断：用户是对的，而且双 Image 的实现本身就是错的。**
旧逻辑在给了 Poster 但**取不到图**（404/断网）时只把 `PosterImage.Visibility` 置为 Visible，
那张图是**空白**的，而底下的占位图已经被 Collapsed —— 于是露出一块空白（实际看到的是 Border 的
`PlayerAccentBrush` 底色），根本不是内置海报。也就是说双层的「回退」只覆盖了"地址为空"这一条路。

改法（`Controls/MusicPlayer/Player.xaml` + `.cs`）：
- XAML 只留一个 `Image x:Name="PosterImage"`，`Source="ms-appx:///Assets/audio_cover.png"` 即默认态，
  加 `ImageFailed="PosterImage_ImageFailed"`。
- 代码：`UpdatePoster()` —— Poster 为空 → `ShowDefaultPoster()`；
  否则 `new BitmapImage(new Uri(poster, UriKind.Absolute))`（格式非法在这里抛，catch 后回退）。
- 新增 `_isDefaultPoster` 标志位：**防止默认海报自己也加载失败时无限回退**。
- `PosterImage_ImageFailed`：非默认态才回退，覆盖「地址合法但取不到图」这条异步路径。

**通用结论**：`BitmapImage` 异步取图，"地址格式错"在 `new Uri` 就抛（try/catch 拦得住），
"404/断网"只会让图变空白 —— **必须挂 `ImageFailed` 才谈得上回退**。
一条 `Image` + 失败回退比叠两层更短也更正确。

验证（`%TEMP%\player-preview`，新增 `PREVIEW_MODE=poster`）：
四态各截一张对照 —— 自定义地址（橙色测试图）/ 非法地址→内置 / 取不到图→内置 / Poster 空→内置，
四种情况都正确。预览里新增 `Assets/test-poster.png`（与默认海报差异很大，便于确认换图生效）。

主工程 `dotnet build` 0 错误，CS 警告无新增。

## 【产物】WinUI 试验工程：`%TEMP%\ubb-editor-preview`

把上面那版设计落到 WinUI，验证"在 TopicPage 上方加浮层"这个方案（替代原来的 `Frame.Navigate(typeof(SketchPage))`）。

工程：`UbbEditorPreview.csproj`（WinExe / 免打包 / 自包含，写法照抄 player-preview）。
文件：
- `UbbEditorOverlay.xaml(.cs)` —— **本轮唯一的产物**：遮罩 + 面板 + 标题栏/工具条/编辑区。
  先只在本目录迭代，稳定后再搬进 `Controls/UbbEditor/`。
- `MainWindow.xaml(.cs)` —— 假的 TopicPage + 底部的"回复"条，浮层作为**最后一个子元素**盖在最上层。
- `shot.py` 从 player-preview 抄来的；`PREVIEW_MODE=split|edit|preview`、`PREVIEW_LANG=ubb|md`、
  `PREVIEW_THEME=light|dark`、`PREVIEW_ANON=1` 控制启动状态。

**这次踩到的坑（都值得记）**：
1. **`TextBlock` 没有 `BorderBrush` / `BorderThickness`**（`Grid` 有，`TextBlock` 没有）——
   想在文本上方画分隔线，得在外面套一层 `Border`。编译器报 `WMC0011: Unknown member 'BorderBrush'`。
2. **用 `Path` 画线性图标时 `Stretch` 必须是 `None`**。几何已经画在 16×16 坐标系里，
   用 `Uniform` 会把"眼睛"这种扁图形按自身包围盒放大，导致各图标大小不一（同一个槽位里忽大忽小）。
3. **`PathIcon` 只能填充、不能描边**，所以线性图标（`M2.5 8 H13.5` 这种）用 `PathIcon` 会完全看不见。
4. **`Path.Stroke` 不参与 `Foreground` 继承**：分段控件里"选中变主色"对文字自动生效，对图标必须
   在代码里改 `Stroke`（`TextBlock`/`FontIcon` 才会跟着 `Foreground` 走）。
5. **收起来的栏位列宽要真的给 0**。第一版 `PreviewColumn.Width = split ? 1* : 0` ——
   切到"预览"时两列都是 0，右边整块空白。正确写法是按模式逐列判断，不是只看 `split`。
   这个是靠截图发现的（逻辑上"看起来对"）。
6. 分段控件的选中态用**主色淡底 + 主色文字**（非主题字典里的纯色资源），
   代码里取 `Resources["EditorAccentSoftBrush"]` 更稳；未选中态的颜色直接从已套样式的按钮上读
   `button.Foreground` / `icon.Stroke`，不去猜主题资源键。

验证：5 张截图（分屏/编辑/预览/Markdown/深色）逐项核对；试验工程构建 0 错误。

## 【小工具】`%TEMP%\ubb-editor-preview\check_window.py`

按 **pid** 找到已经跑起来的窗口 → 打印标题/可见/最小化/位置 → `ShowWindow(SW_RESTORE)` +
`SetForegroundWindow` 置前 → `PrintWindow` 截一张图。用法：

```
python check_window.py <pid> <out.png>
```

和 `shot.py` 的区别：`shot.py` 是"我启动一个进程再截图"（用完就杀），
`check_window.py` 是"你手动开着窗口，我只把它端到前面看一眼再截图"。
用户说"打开测试工程"时就用这个确认窗口真的渲染出来了。
（附注：`shot.py` 没有 `if __name__ == "__main__"` 保护，`import shot` 会直接跑 main 并因为
缺 argv 而抛 IndexError —— 想在别的脚本里复用它得先补上这个 guard。）

启动试验工程的正确姿势（`cmd //c start` 在 Git Bash 里会被路径转换搞乱，别用）：
用 Python `subprocess.Popen(..., creationflags=DETACHED_PROCESS|CREATE_NEW_PROCESS_GROUP, close_fds=True)`，
启动前把 `PREVIEW_*` 环境变量清掉，否则会沿用上一次截图时的状态。
