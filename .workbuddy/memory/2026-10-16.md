## 核查 UbbTextBlock 属性解析能力（主属性 / 键值对属性）

需求：`[img=1]`、`[img="http…"]`、`[topic=1029383]` 这类「主属性」，以及
`[audio,title=…,author=…]url[/audio]` 这类「键值对属性」（顺序无关，需落到属性字典）。

核查方式：建临时探针工程 `%TEMP%\ubb-attr-probe`（`EnableDefaultCompileItems=false`，
直接 Compile Include 仓库里的 `Tokenizer/*.cs` + `Parser/*.cs`，纯 C# 无 WinUI 依赖），
打印 Token 流 + AST 属性字典逐条比对。

结论：**部分满足，需求未全部实现**。

已可用：
- 主属性（不加引号）：`[img=1]`、`[img=url]`、`[topic=1029383]`、`[color=#f00]`、`[size=5]`
  → 落到 `value`（按类型经 `UBBParser.GetAttributeName` 映射为 href/color/size/font/language/author）。

缺陷：
1. 【P0】键值对属性完全没拆。`[audio,title=X,author=Y]` →
   `value="title=X"`、`value1="author=Y"`。键是 `value{n}` 而非 `title`/`author`，
   且谁在前谁拿 `value`（顺序敏感）。根因：`Tokenizer.IsTagDelimiter` 只在
   `_lastType == LeftBracket/Slash` 时把 `=` 当分隔符，逗号后整段 `key=value` 被扫成一个 AttrValue；
   解析器又只按 `attrCount` 编号。
2. 【P0】属性值不去引号。`[img="http://…"]` → `value="\"http://…\""`，
   `ImageRenderStrategy` 的 `IsValidUrl` 判定失败 → 图片不渲染；`[topic="1029383"]` 同理被丢弃。
3. 【P1】值前后空格不裁剪：`[audio, title=X , author=Y ]` → 值带空格。
4. 【P1】引号内逗号被当分隔符：`[audio,title="虽然,歌声"]` 被切成两个属性。
5. 【P2】主属性里的逗号会截断值：`[url=https://a.com/x,y]` → `href="https://a.com/x"` + `value1="y"`。
6. 【P2】渲染层下游未适配：`AudioRenderStrategy:806` 仍是
   `title.Replace("title=", "")` 的特判 hack；`MusicPlayer` 只有 `Title`，没有 author 展示位。

建议修复（最小改动面）：
- `Tokenizer.ScanTagContent`：引号感知（仅将 `"` 视作成对引号，**不要**把 `'` 视作引号，
  否则 `title=Don't Stop` 之类的撇号会吞到 EOF）。
- `UBBParser.ParseTagHeaderOrFallback`：区分分隔符——`Equal` 进来的是主属性
  （key 走 `GetAttributeName`），`Comma` 进来的是键值对（在该 AttrValue 的**第一个** `=` 处切分，
  key/value 各自 Trim + 去引号）；无 `=` 时回退 `value{n}` 保持兼容。
- `RenderStrategy.AudioRenderStrategy`：改读 `title` / `author` 命名属性，删掉 `Replace` hack。

其他发现：未知标签（如 `[content,type=a]`）会整体回退成文本，属预期行为。

## 【需求澄清】引号不是 UBB 语法

用户澄清：**附加属性一般没有引号，引号只是普通字符串，不在 UBB 语法里**，
所以上面第 2、4 条（去引号 / 引号内逗号）**不作处理**。
真正要解决的是：**逗号到底是不是属性边界**——`title=Hello, World,author=A` 里第一个逗号属于标题内容。

## 【已实施】主属性 + 键值对属性解析

改动 3 个文件，主工程 `dotnet build` 0 错误、探针 36/36 通过。

1. `Tokenizer/Tokenizer.cs`
   - 新增 `IsCommaBoundary()`：逗号是边界 ⇔ 逗号前是标签名（含 `[`、`[/`），
     或逗号之后匹配「键名 空白* =」（键名 = 除空白、`, = ] [ $ /` 外的任意字符）。
   - `IsTagDelimiter` 与 `ScanInTag` 的 `case ','` 都改走该判定；**不构成边界时逗号归入属性值**。
   - 效果：`title=Hello, World,author=A` → `title="Hello, World"`；`[url=https://a.com/x,y]` 也不再截断。
2. `Parser/UBBParser.cs`
   - 属性循环改为记录**分隔符类型**：`=` 后是主属性（键走 `GetAttributeName`），
     `,` 后是键值对，交给新增的 `AddKeyValueAttribute`。
   - `AddKeyValueAttribute`：在**第一个** `=` 处切分，键值各自 `Trim`；无键名时回退
     `GetAttributeName(type)` / `value{n}` 保持兼容（`[code,csharp]` 仍得到 `language=csharp`）。
   - 主属性值也 `Trim()`。
   - 键名大小写保持原样，不做归一化。
3. `Common/RenderStrategy.cs`
   - `AudioRenderStrategy` 改读 `title`（回退 `value`），删掉 `Replace("title=", "")` 补丁。

**遗留 / 已知边界**
- `[audio,title=Hello, World = 1]` 这类「值里出现 `, 词=」」会被当成边界（title="Hello" + World="1"）。
  无引号语法下无法两全，接受。
- `author` 已能解析但**无处展示**：`MusicPlayer` 只有 `Title`，没有 Author 属性（未改，等需求）。
- Audio 的 src 仍只取子节点纯文本，未回退 `value` 属性（用户明确：audio/video 不支持主属性 src，不补）。

## 【已实施】子节点里的地址取不到（audio/topic/url/img/video/upload）

问题：渲染层一律写 `node.FirstChild is TextNode` 去子节点取地址，
`[img][b]http://…[/b][/img]`、`[url][color=red]http://…[/color][/url]` 这种带样式嵌套就取不到；
audio 更狠，直接把整个节点丢掉不渲染。

改动：
1. **新增** `Parser/UbbNodeTextExtensions.cs`：把原 `RenderHelper.CollectText` 的递归实现搬过来，
   做成 `public static string CollectText(this UbbNode node)`。放 `Parser/` 是因为它纯 C#、
   不引用 WinUI，**能被探针工程直接编译测试**。
2. `Common/RenderHelper.cs`：`CollectText` 改为一行委托；新增
   `ResolveAddress(TagNode, attributeKey, allowRelative)`＝「主属性是合法地址就用，否则回退子节点全文」。
3. `Common/RenderStrategy.cs`：
   - `UrlRenderStrategy` / `ImageRenderStrategy` / `FileRenderStrategy` → 改用 `ResolveAddress`。
   - `AudioRenderStrategy` → `src = CollectText(tagNode)`，空串直接 return（不再要求首子节点是 TextNode）。
   - `VideoRenderStrategy` → 子节点回退改用 `CollectText`（主属性那路保持原样，未动）。
   - `TopicRenderStrategy` → 主题号主属性为空时回退子节点文本；ID 非法时**按普通文本渲染子节点**
     而不是直接 return 丢内容。顺带修掉 `"".All(char.IsDigit) == true` 导致的 `/topic/` 死链。

验证：探针 **46/46 通过**（新增 11 条，直接调用仓库里真实的 `UbbNodeTextExtensions.CollectText`）；
主工程 `dotnet build` 0 错误，**唯一警告 68 条与改动前一致**（汇总行显示 136 是因为 XAML 与 C# 两趟各报一遍，
`sort -u` 后仍是 68）。
