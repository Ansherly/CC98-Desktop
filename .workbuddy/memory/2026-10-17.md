## 【试验工程】编辑器浮层按 SketchPage 的既有做法重做

用户提了 5 条修正，全部落在 `%TEMP%\ubb-editor-preview`（主工程仍未动一行）。

### 改了什么

1. **图标不再手画**：改用 `ic:SymbolIcon`（`FluentIcons.WinUI`），名称直接照抄 SketchPage
   （TextAlignLeft/Center/Right、CommentQuote、Code、Link、Image、MoviesAndTv、Document、
   Stream、MusicNote2、LineDashes、Emoji、ArrowUpload、Dismiss、Edit、LayoutColumnTwo、Eye）。
2. **UBB/MD 用 `controls:Segmented`**（`CommunityToolkit.WinUI.Controls.Segmented`）；
   编辑/分屏/预览也换成同一个控件，视觉才统一（圆角组 + 选中项底部主色条）。
3. **匿名改成 `CheckBox`**（原来是 ToggleSwitch）。
4. **删掉 UBB 语法提示**；工具条去掉 H1/H2 —— UBB 根本没有标题标签。
   按钮集合改成 SketchPage `AppBarButton_Click` 里真正支持的那些：
   粗体/斜体/下划线/删除线｜左中右对齐｜引用/代码/链接｜图片/视频/音频/文档/哔哩/分割线/表情｜上传。
5. **两栏宽度用 `GridSplitter`**（`CommunityToolkit.WinUI.Controls.Sizers`）。
   Sizers 包里三个候选：`ContentSizer`、`PropertySizer`、`GridSplitter`。
   官方文档明确写了「如果在用 Grid，就用 GridSplitter，别用另外两个」，
   而本布局正是两列 Grid、SketchPage 那个 `PropertySizer` 是绑 `SplitView.OpenPaneLength` 的，场景不同。

### 踩到的坑（都值得记）

- **`Segmented` 的选中不能靠 `SelectedIndex`**。XAML 里给 `SelectedIndex="0"` 也会被控件自己的
  "加载后补一次选中"覆盖；事件回调里读 `SelectedIndex` 拿到的值也对不上（表现成"UBB 明明选中，
  源码栏却写着 Markdown 源码"）。正解：**XAML 用 `IsSelected="True"`**，事件里读
  `e.AddedItems[0] as SegmentedItem` 的 `Tag`，代码回写时遍历 `Items` 改 `IsSelected`
  （加 `_syncing` 标志位防重入），最后在 `Loaded` 里强制同步一次。
- **`AppBarButton` 默认 48×48**，19 个按钮直接把工具条撑爆，右侧 Segmented 被挤出可视区。
  用 `Style BasedOn="{StaticResource DefaultAppBarButtonStyle}"` 压到 34×34 + `MinWidth=0`。
  （`DefaultAppBarButtonStyle` 这个 key 确实存在。）
- **`LabelPosition` 只有 `Default` / `Collapsed`**，没有 `Right`。想要"图标 + 文字横排"
  只能换成普通 `Button` 里塞 StackPanel。
- **`Symbol` 是两套枚举**：`Bold` / `Italic` / `Underline` 在 **Microsoft** 的
  `Microsoft.UI.Xaml.Controls.Symbol` 里，**FluentIcons 的 Symbol 枚举没有这三个**；
  写 `ic:SymbolIcon Symbol="Bold"` 会报 `WMC0055: Cannot assign text value 'Bold'`。
  SketchPage 也是用 `Icon="Bold"`（Microsoft 那套）而不是 `ic:SymbolIcon`。
- 校验图标名是否存在的笨办法但有效：把 `FluentIcons.Common.dll` 读成 bytes，
  数 `b"Name\0"` 出现次数 —— 枚举名在 #Strings 堆里是 NUL 结尾的。

### 设计稿同步

`桌面\CC98 UBB编辑器浮层.html` 一并对齐：去掉 H1/H2 与语法提示、匿名改 checkbox、
工具条换成 SketchPage 那套、分段控件改成同样的"组 + 底部主色条"、两栏之间加可拖分隔条
（pointerdown/move 实现，对应 WinUI 的 GridSplitter）。

**用 Edge 无头模式自查 HTML**（比开浏览器快）：
```
msedge --headless=new --disable-gpu --hide-scrollbars \
       --virtual-time-budget=2500 --window-size=1280,860 --screenshot=out.png "file:///..."
```
必须给 `--virtual-time-budget`：面板有入场动画（`animation: fade/rise`），
不给的话截到的是 opacity≈0 的第一帧，整个浮层看起来"没背景、没遮罩、错位"，
会据此得出完全错误的结论。

## 【试验工程】工具条图标大小统一

用户：「图标大小不均匀，保持 button 大小不变，缩小其余的 icon」。
病根是 **FluentIcons 的 `SymbolIcon` 默认按 `FontSize=20` 绘制**，而哔哩 SVG 的 `Image` 是 18
（且 24 viewBox 自带留白，实际墨迹 16 DIP）—— 于是旁边那批图标全都比哔哩大一号。

改法：工具条里所有图标统一到 **16**，按钮 34×34 不动。
- `ic:SymbolIcon` 直接设 `FontSize="16"`（14 个）。
- **Microsoft 的 `SymbolIcon`（Bold/Italic/Underline 用的那套）没有 `FontSize` 属性**
  （报 `WMC0011: Unknown member 'FontSize' on element 'SymbolIcon'`），
  只能套 `<Viewbox Width="16" Height="16">` 缩放。

实测墨迹高度（物理 px，2x DPI；改前 → 改后）：
B/I/U/S 34→28、对齐 27→22、引用 37→30、代码/链接 20→16、图片 34→28、
视频 40→32、文档 40→32、哔哩 SVG 32→32（不变）、颜色 38→31、表情 40→32。
即最大的一批从 20 DIP 降到 16 DIP，**和哔哩 SVG 齐平**；剩下的差异是字形本身留白不同
（`</>` 和链接天然小、对齐是三条横线），不是尺寸没设对。

## 【修复】块级标签（[align=] 等）插入时多出空行

现象：插 `[align=left]` 系列时凭空多一行空行。

原因：`MarkupEditing.Block` 里写死了 `"\n" + open + content + close + "\n"`，
**不管光标在哪都加**。空文档里插一次就变成 `\n[align=center][/align]\n` —— 前后各一行空白。

修法（`Block` / 新增 `BlockLiteral` / `QuoteMd` 共用两个小判据）：
- `NeedsLeadingNewline(text, index)`：只在 `index > 0 && text[index-1] != '\n'`（不在文首、不在行首）时补；
- `NeedsTrailingNewline(text, index)`：只在 `index < text.Length && text[index] != '\n'`（后面不是换行/文末）时补。

同时把 MD 分隔线 `"\n---\n"` 换成 `BlockLiteral(text, start, length, "---")`，
引用也改成同一套判据 —— 否则只修 align，quote/---/代码块还是会产生同样的空行。

探针补到 **25 条**（新增 6 条专测块级换行：空文档 / 行中间 / 行首 / 后面有内容 / 后面已是换行 / MD 各一处），
25/25 通过。`dotnet build` 0 错误。

### 5MB 大小限制的审计结果

`MaxUploadSizeBytes = 5 * 1024 * 1024` = **5,242,880**（5 MiB），int 运算不会溢出；
两处比较都是 `>`，所以**恰好等于上限的文件能过**。算术本身没错。

真正可疑的地方：
1. **MiB vs MB**：如果服务端按 5,000,000 字节算，我们放行到 5,242,880 →
   5.0–5.24MB 的文件本地判过、服务端拒。这才是"看起来误判"的来源（方向是"放得太宽"，不是"卡太严"）。
2. 原 `TooLarge` 文案把 `MaxUploadSizeBytes/1024/1024` 说成 "5MB"，和真实字节数不一致，容易误导。
3. 剪贴板位图走的是"复制原始字节 → 临时文件 → 再判大小"，如果剪贴板只给 DIB（截图工具/部分浏览器）
   会被编码成 PNG 落盘，体积变大后被判超限 —— 用户视角就是"明明不大却超限"。

改动：加了 `MaxUploadSizeText`（文案与常量同源）+ `IsOverSizeLimit(long)`（两处判据统一），
`TooLarge` 现在提示「超过 5MB(5,242,880 字节)上限」。

## 【修复】剪贴板大图被 5MB 拦下的正确解法（DIB → 重新编码）

用户确认：「截图/浏览器复制只给 DIB 的话，落盘会变成 PNG，体积比原图大」成立。

**改法：`FileUploadService.UploadClipboardBitmapAsync` 重写成「先原样、再降级」，并且不再落临时文件**
（直接 `UploadStreamAsync(new MemoryStream(bytes))`）：
1. 原始字节没超限 → 原样传，一个像素都不动；
2. 超限 → 按缩放台阶重编码：有 alpha 走 PNG(100/70/50%)，否则 JPEG(100/70/50/35%)；
3. 全都不行 → 报错并提示改用「上传本地文件」或先裁剪；
4. 用了缩放就通过 `UploadResult.Note` 告诉用户「已缩到 N% 上传」。

### 探针结论（%TEMP%\clipbitmap-probe，net10.0-windows + WinRT，可直接跑）

- **`BitmapPropertySet["ImageQuality"]` 完全无效**：q=1.0/0.6/0.2 编出来的字节**一模一样**（360.3 KB），
  设在 `SetPixelData` 之前或之后都一样。→ 别再用质量降级，这条路是死的。
- **`BitmapTransform.ScaledWidth/ScaledHeight` 有效**：1600×1200 → 100%/70%/50%/35% 得到
  637/246/105/65 KB，单调递减 ✓
- PNG 用 `BitmapAlphaMode.Premultiplied` 编出来正常（保住透明）✓
- 踩坑：`ReadAllBytesAsync` 不能用 `AsStreamForRead()`——那个适配流 Dispose 会把底层流关掉，
  而后面还要用同一个流给 `BitmapDecoder` 取像素，会直接炸。改成 `DataReader` + `DetachStream()`。
- 踩坑：`BitmapInterpolationMode` 没有 `Fair`，只有 `NearestNeighbor/Linear/Cubic/Fant`；
  `PropertyType` 要 `using Windows.Foundation;`。
- 探针里如果直接拿裸 BGRA 字节喂 `BitmapDecoder`，会报 `0x88982F50`（未知图片格式）——
  必须先编成 PNG 再解码。

## 【主工程】接入「编辑帖子」：区分主题 vs 回复

入口是回复项右键菜单里的「编辑」（`PostOperation_Click` 的 `Tag="EDIT"`，仅 `IsMe` 可见）。
**首楼（Floor == 1）就是主题本身**——TopicPage 顶部只显示标题+元信息，正文由回复列表里的首楼渲染，
所以 `EditMyTopic` 只能从首楼的菜单进（`TopicInfo` 那边没有编辑入口）。

`PostOperation_Click` 的 EDIT 分支不再 `Frame.Navigate(SketchPage)`，改成开浮层：

```csharp
var editingTopic = reply.Floor == 1;
ComposeOverlay.Mode = editingTopic ? EditorMode.EditMyTopic : EditorMode.EditMyPost;
ComposeOverlay.PostId = reply.Id;
ComposeOverlay.InitialTitle = editingTopic ? TopicInfo.Title : "";
ComposeOverlay.Prefill(reply.Content ?? "", reply.ContentType);
ComposeOverlay.Show();
```

`ComposeSheet.ConfigureForMode()` 现在分三种形态：

| Mode | 状态栏文案 | 标题行 |
| --- | --- | --- |
| ReplyToTopic / ReplyToPost | 回复主题 | 收起 |
| EditMyPost | 编辑回复 | 收起（回复没有标题） |
| EditMyTopic | 编辑主题 | **展开并回填原标题** |

两个容易漏的点：
1. `SetTitleEditing(false)` **必须同时把标题清空**，否则上一次编辑主题留下的标题会跟着发进回复。
2. 上一次是编辑、这一次是回复时要 `Editor.Reset()`（`_editingLastTime` 标记），不然编辑的原文会串成新回复的内容。

`Sent` 之后改成 `LoadTopicInfo() + LoadReply()`——编辑主题会改标题和正文，只刷列表不够。

接口上不分主题/回复：两者都是 `PUT /post/{postId}` + `EditPostRequest`，
只是主题要多传 `Title`（回复传空串，和 SketchPage 一致）。

## 【修复】收起后预览残留 + 编辑时语言/匿名没带过去

**① 预览残留**：`Hide()` 之后预览栏还挂着上次的排版（`UbbViewer.UbbText` / `PreviewScroller` 都是可见的），
下次打开先闪一下再消失 —— 因为 `EditorBox.Text = ""` 触发的预览刷新有 **300ms 防抖**。

- 新增 `ComposeEditor.ClearPreview()`：停防抖 + 收 `PreviewScroller` + 清两个 viewer 的文本；
- `Reset()` 里立刻调用（不再等防抖）；
- `Hide()` 动画结束时**无条件**调一次（草稿文本留着，但渲染结果不该过夜）；
- 草稿场景下靠 `Show()` 动画结束时的 `Editor.RefreshPreview()` 补回来（新方法：停防抖 + 立刻 `RenderPreview()`）。

**② 编辑时状态没搬全**：`Prefill(content, contentType, isAnonymous)` 现在三样一起给
（`ContentType` / `ContentText` / `IsAnonymous`），`TopicPage` 传 `reply.IsAnonymous`。

**③ 「编辑 MD 帖子却用 UBB 预览」的真正原因**：浮层第一次显示时模板才实体化，
`Segmented` 会按 XAML 里的 `IsSelected="True"`（UBB）再抛一次 `SelectionChanged`，
把 `_contentType` 从 MD 拉回 UBB。`SyncSelection` 的 `_syncing` 拦不住（事件是实体化时抛的）。
修法：`Show()` 里先记下 `var language = Editor.ContentType;`，动画结束后
`if (Editor.ContentType != language) Editor.ContentType = language;` 再断言一次。

注意 `EditPostRequest` 里**没有 IsAnonymous 字段**，所以编辑时匿名单选框只是"如实显示"，
改它不会生效（服务端不支持）。
