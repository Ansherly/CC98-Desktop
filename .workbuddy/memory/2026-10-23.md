## 【修复】换行/空白处理对齐 SketchPage

用户报「一些该换行的地方没换行」。逐条比对 SketchPage 后找到三处真实差异：

**① 换行没归一化（主因）**
SketchPage 的 `TextContent = Editor.Text.Replace("\r\n","\n").Replace("\r","\n")` —— 渲染和提交都走它。
我们直接把 `EditorBox.Text`（带 `\r\n`）丢给 `UbbTextBlock` / `MarkdownTextBlock` 和请求体。
→ `ComposeEditor.ContentText` 的 getter 改成归一化，`RenderPreview` 也改用 `ContentText`。

**② 块尾换行在文末被省掉了**
我把 `NeedsTrailingNewline` 写成 `index < text.Length && …`，文末不补。
MD 的 `` ``` ``、`<div>`、`---` 都是「到行尾才收尾」，后面不留换行会把之后输入并进块里
（` ```code```text ` 的收尾围栏失效，整段被吞进代码块）。
→ 改成 `index >= text.Length || text[index] != '\n'`（文末必补，后面已是换行则不重复）。

**③ MD 分割线必须隔一个空行**
`abc` 紧跟 `---` 在 Markdown 里是 **setext 二级标题**，不是分割线。
→ `BlockLiteral` 新增 `LeadingBlankLine()`：数插入点前面的连续换行，0 个补 `\n\n`、1 个补 `\n`、
已经有空行就不补、文首不补。探针补到 **27 条**（新增空文档/行首/已有空行三种分隔线场景），27/27 通过。

### 与 SketchPage 仍然不同的地方（有意为之）

- 块级插入**前导换行按需补**（SketchPage 无条件补，空文档会多一条空行 —— 这是之前报的那个 bug）；
- 块级插入后**光标落在整块之后**（SketchPage 把光标留在块内/分割线行尾，接着打字会写进块里）；
- 行内包裹**会包住选中内容**（SketchPage 的 UBB `InsertTag` 完全忽略选区）。

### 工具坑

用 bash heredoc 跑 Python 改 C# 代码时，`\r\n` 会被还原成真正的换行写进文件（`ContentText` 那次就被写坏了）。
**要改含转义序列的 C# 代码，只用 Edit/Write 工具，或者先 Write 一个 .py 再执行。**
